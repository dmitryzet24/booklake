# BookLake — BL-003: Book Catalog Builder

> **Статус:** `TODO` · **Язык:** C · **Контекст:** 42 Porto / Exam Rank 02 · **Релиз:** BookLake `v0.3` (учебный каталог)
>
> **Цель:** реализовать импорт записей о книгах из строк с разделителем `|` в односвязный список, сохраняя пустые поля, проверяя качество данных и корректно управляя памятью.

## 1. Зачем это нужно

BookLake — учебная платформа для каталогизации больших коллекций документов. В этой задаче мы создаём **маленький, но законченный компонент ingestion**: `raw record → split → validation → book node → linked list → operations → cleanup`.

Мы учим C не ради готовой библиотеки: алгоритмы и владение памятью должны быть понятны настолько, чтобы написать их самостоятельно в условиях Exam Rank 02. **Не присылай готовое решение, пока я явно его не попрошу:** на ревью сначала укажи на конкретный тест, инвариант или ошибку, затем дай наводящий вопрос.

### Границы задачи

- Данные пока хранятся в массиве строк в `main`, без файлового ввода, Calibre, SQL и сети.
- Строки — байтовые последовательности C; UTF-8 не разбираем по символам.
- Разделитель — один байт `|`; экранирование и кавычки в этой версии не поддерживаются.
- Внешние зависимости для бизнес-логики не нужны; для тестов можно использовать стандартные инструменты Linux.

## 2. Формат входа и контракт данных

Каждая запись имеет **ровно три поля**, включая пустые:

```text
TITLE|AUTHOR|YEAR
Dune|Frank Herbert|1965
Dune||1965
|Unknown Author|1950
Solaris|Stanislaw Lem|
||
```

**Ключевое правило:** пустое поле не исчезает. В частности, `Dune||1965` — это `title="Dune"`, `author=""`, `year="1965"`.

| Строка | Результат split | Итог импорта |
|---|---|---|
| `Dune|Frank Herbert|1965` | `Dune`, `Frank Herbert`, `1965` | Добавить |
| `Dune||1965` | `Dune`, ``, `1965` | Добавить; автор отсутствует |
| `|Unknown Author|1950` | ``, `Unknown Author`, `1950` | Добавить; название отсутствует |
| `Solaris|Stanislaw Lem|` | `Solaris`, `Stanislaw Lem`, `` | Добавить; год отсутствует |
| `||` | ``, ``, `` | Добавить; все три поля пустые |
| `Dune|Herbert` | 2 поля | Отклонить: неверное число полей |
| `Dune|Herbert|1965|extra` | 4 поля | Отклонить: неверное число полей |
| пустая строка `""` | 1 пустое поле | Отклонить: неверное число полей |
| `Dune|Herbert|19x5` | 3 поля | Отклонить: некорректный год |

**Важно:** `""` в `char **fields` — выделенная строка из одного байта `\0`, **не** `NULL`. `NULL` завершает массив указателей. Для отсутствующего года используем отдельный флаг, а не число `0` как неявный признак отсутствия.

Год: если поле непустое, допускаются только десятичные цифры и диапазон `1..9999`. Это учебное правило валидации, а не историческая модель датировки книг. Пробелы в годе пока не допускаются. Название и автор могут быть пустыми; пробелы внутри полей пока не нормализуем.

## 3. Структуры и API

Файл `booklake.h`:

```c
#ifndef BOOKLAKE_H
# define BOOKLAKE_H

typedef struct s_book
{
    char            *title;
    char            *author;
    int             year;
    int             has_year;
    struct s_book   *next;
}   t_book;

/* Этап A: split с сохранением пустых полей */
char    **book_split(const char *s, char delimiter);
void    free_fields(char **fields);
int     count_fields(const char *s, char delimiter);

/* Этап B: создание узла; при успехе копирует title/author */
t_book  *create_book(const char *title, const char *author,
            int year, int has_year);

/* Этап C: список */
void    book_add_back(t_book **head, t_book *node);
int     book_count(t_book *head);
void    print_catalog(t_book *head);
void    free_catalog(t_book *head);

/* Этап D: импорт */
int     import_book(t_book **head, const char *line);

/* Этап E: операции с каталогом */
t_book  *find_book_by_year(t_book *head, int year);
int     remove_book_by_title(t_book **head, const char *title);
void    sort_books_by_year(t_book **head);

#endif
```

**Выбранный контракт владения памятью:** `book_split` выделяет массив и все строки; `create_book` создаёт узел и **копирует** `title`/`author` в собственную память. Поэтому вызывающий код всегда освобождает `fields` через `free_fields`, независимо от результата создания узла. Это чуть больше работы, зато меньше неоднозначности и риска double free. `free_catalog` освобождает обе строки и каждый узел. Если выделение памяти не удалось, функции не оставляют частично созданных объектов.

Для `import_book`: `0` — запись добавлена, `1` — ошибка формата/валидации, `2` — ошибка выделения памяти. При ошибке список должен остаться без изменений.

## 4. Этапы реализации

### A — Split и границы полей

- [ ] Реализовать `count_fields`: количество полей = количество разделителей + 1, включая пустые.
- [ ] Реализовать `book_split` с `malloc` для массива указателей и каждого поля.
- [ ] Добавить `NULL` после последнего поля.
- [ ] Реализовать `free_fields`.
- [ ] Корректно освободить уже выделенные поля, если очередной `malloc` не удался.
- [ ] Протестировать начало, конец и повторяющиеся разделители, пустую строку, отсутствие разделителя.

**Экзаменационная параллель:** отдельно реализовать классический `ft_split` с пропуском пустых токенов. Не смешивать два контракта в одной функции.

### B — Валидация и создание книги

- [ ] Проверять **ровно 3 поля**.
- [ ] Реализовать безопасный разбор года без `atoi` (отличать пустое поле от неправильного числа).
- [ ] Различать `has_year = 0` и `has_year = 1`.
- [ ] Создать узел с `next = NULL` и независимыми копиями строк.
- [ ] При любой ошибке выделения памяти освободить всё созданное.

### C — Односвязный список

- [ ] `book_add_back`: добавить в пустой и непустой список, сохранить порядок.
- [ ] `book_count`: посчитать узлы, не изменяя список.
- [ ] `print_catalog`: вывести каждую книгу, для пустых полей использовать `[missing title]`, `[missing author]`, `[unknown year]`.
- [ ] `free_catalog`: освободить весь список без use-after-free.

### D — Импорт нескольких записей

- [ ] `import_book`: split → проверка → parse → create → append → cleanup.
- [ ] Невалидные строки не должны попадать в список.
- [ ] Ошибка одной записи не должна ломать импорт следующих.
- [ ] В `main` импортировать тестовый массив и вывести число успешных/отклонённых записей.

### E — Операции с каталогом

- [ ] `find_book_by_year`: вернуть первую книгу указанного года либо `NULL`.
- [ ] `remove_book_by_title`: удалить **первое точное совпадение**, освободив узел и строки; обработать удаление головы, середины, хвоста и отсутствие совпадения.
- [ ] `sort_books_by_year`: отсортировать по возрастанию; записи без года — в конце; порядок равных годов сохранять (стабильная сортировка).
- [ ] После каждой операции список остаётся корректным и полностью освобождается.

**Для сравнения названий** разрешено написать минимальную локальную функцию равенства строк; отдельный учебный блок `ft_strcmp` не требуется.

## 5. Тестовые данные

```c
const char *records[] = {
    "Dune|Frank Herbert|1965",
    "Foundation|Isaac Asimov|1951",
    "Solaris|Stanislaw Lem|1961",
    "Neuromancer|William Gibson|1984",
    "Dune||1965",
    "|Unknown Author|1950",
    "Solaris|Stanislaw Lem|",
    "||",
    "Dune|Herbert",
    "Dune|Herbert|1965|extra",
    "Dune|Herbert|19x5",
    NULL
};
```

Ожидается **8 успешно импортированных записей, 3 отклонённых**. До операций удаления и сортировки список должен сохранять порядок входных строк. При печати неизвестные значения обозначаются явно, но в памяти пустые `title`/`author` остаются пустыми строками.

Дополнительные обязательные тесты:

- `book_split("", '|')` → один элемент `""` и завершающий `NULL`;
- `book_split("||", '|')` → три пустых элемента и `NULL`;
- `book_split("Dune||1965", '|')` → три элемента, средний пустой;
- импорт с невалидным годом и неправильным количеством полей не изменяет `book_count`;
- удаление из пустого списка и удаление единственного узла;
- сортировка пустого списка, одного узла, одинаковых годов и записей без года;
- повторный вызов `free_fields(NULL)` и `free_catalog(NULL)` безопасен.

## 7. Сборка и проверка

В `Makefile` должны быть цели `all`, `clean`, `fclean`, `re`, `test`. Сборка с `-Wall -Wextra -Werror`.

Для ручной проверки памяти (выполнять из `core/bookcatalog` после реализации исходников):

```bash
cc -Wall -Wextra -Werror -g -fsanitize=address,undefined \
  *.c -o bookcatalog_asan
./bookcatalog_asan

cc -Wall -Wextra -Werror -g *.c -o bookcatalog_valgrind
valgrind --leak-check=full --show-leak-kinds=all \
  ./bookcatalog_valgrind
```

Ожидаем отсутствие ошибок санитайзеров, `invalid read/write`, `double free`, `use-after-free`, утечек. Проверяем также `norminette` там, где это применимо. **Не полагаемся только на красивый вывод программы.**

## 8. Критерии готовности релиза

- [ ] Сохраняются все пустые поля и позиции колонок.
- [ ] Строки с неправильным количеством полей отклоняются без изменения списка.
- [ ] Некорректный год отклоняется; отсутствующий год сохраняется явно.
- [ ] Порядок импорта сохраняется до явной сортировки.
- [ ] Поиск, удаление и стабильная сортировка работают на крайних случаях.
- [ ] Нет утечек памяти и недопустимых обращений по результатам тестов.
- [ ] Сборка без предупреждений; тесты запускаются одной командой.
- [ ] Код объясним: указатели, двойные указатели, `malloc/free`, сложность алгоритмов.
